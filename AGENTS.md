# Локальный контекст проекта

Этот файл задаёт локальные правила проекта `obsidian-gdrive-sync` и имеет приоритет внутри его папки. Он дополняет корневой `D:\opencode\AGENTS.md`.

## Назначение проекта

- Плагин Obsidian для двусторонней синхронизации vault с Google Drive через собственные OAuth-креденшелы пользователя.
- Целевые платформы: Windows, macOS 13+, iOS.
- Цель дальнего горизонта: публикация в community plugins.
- Текущий этап: исследование и архитектура (этап 01), см. `PLAN.md` и `STAGE_CONTEXT.md`.

## Приоритет источников

1. Последнее прямое сообщение пользователя.
2. Этот `AGENTS.md`.
3. Корневой `D:\opencode\AGENTS.md` и `WORKFLOW_RULES.md`.
4. `SESSION_CONTEXT.md`, `STAGE_CONTEXT.md`, `SUBSTAGE_CONTEXT.md`.
5. `docs/ARCHITECTURE.md` и `docs/COMPARISON.md` как зафиксированные проектные решения.

## Жёсткие технические рамки

- OAuth scope только `https://www.googleapis.com/auth/drive.file`. Не добавлять `drive`, `drive.readonly`, `drive.metadata.readonly` без прямого решения пользователя.
- Пользователь использует свои OAuth-креденшелы. Плагин не должен требовать инфраструктуру автора (relay-серверы, подписки).
- Runtime-код плагина не использует Node API (`fs`, `http`, `net`, `child_process`). Только Obsidian API и `requestUrl`, чтобы работали desktop и mobile.
- Целевой JavaScript — ES2018 (запас совместимости для mobile и старых Electron, хотя целевые устройства — macOS 13+).
- Никаких безвозвратных удалений пользовательских данных. Drive — `trashed=true`, локально — `.trash`.
- Токены, client secret и состояние синхронизации не попадают в git и не синхронизируются плагином в Drive.

## Правила разработки

- Сначала документация и решение, потом код. Архитектурные изменения фиксируются в `docs/ARCHITECTURE.md` и, при необходимости, в `SESSION_CONTEXT.md`.
- Нельзя заявлять о работоспособности без реальной проверки. Степень проверки указывается явно (собрано / запущено в Obsidian / протестировано на устройстве).
- Тесты логики (алгоритм, парсинг, state) — в `tests/`, без сети; сетевые моки Drive adapter.
- Промпты и инструкции для агента — только в `prompts/`.
- Документация на русском, имена в коде и комментарии на английском.
- Не запускать watch-режимы (`npm run dev`) в автоматизации; сборка — только `npm run build`.

## Проверка перед выдачей результата

- Сборка `npm run build` проходит.
- Нет секретов и локальных путей в репозитории.
- Изменения не ломают заявленные платформы (desktop + mobile).
- Обновлены `SUBSTAGE_CONTEXT.md` и `PLAN.md`, если изменилось состояние этапа.
