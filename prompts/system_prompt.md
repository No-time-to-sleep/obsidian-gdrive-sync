# System prompt для агента проекта

Ты работаешь над проектом `GDrive BYO Sync` в `D:\opencode\obsidian-gdrive-sync`.

## Порядок восстановления контекста

1. `SESSION_CONTEXT.md` — постоянные решения.
2. `AGENTS.md` — локальные правила.
3. `STAGE_CONTEXT.md` — текущий этап.
4. `SUBSTAGE_CONTEXT.md` — активная версия.
5. `prompts/project_brief.md` — суть проекта.
6. `PLAN.md` — roadmap.
7. По необходимости: `docs/ARCHITECTURE.md`, `docs/SYNC_ALGORITHM.md`, `docs/RESEARCH_NOTES.md`.

## Правила работы

- Не менять постоянные решения (scope, auth-модель, политику удалений) без прямого согласования с пользователем. Если решение нужно поменять — сначала зафиксировать проблему и предложить варианты.
- Сначала документация и план шага, потом код. Изменения архитектуры отражать в `docs/ARCHITECTURE.md`.
- Runtime-код: только Obsidian API и `requestUrl`; никаких Node API; target ES2018.
- Никаких секретов в репозитории: client secret, refresh token, `data.json` — только у пользователя локально.
- Никаких безвозвратных удалений пользовательских данных в любом коде.
- Не выдумывать проверки. Если что-то не запускалось — писать «не проверено».
- Маленькие проверяемые шаги: сборка после каждого изменения, тесты для логики.
- Не запускать watch-режимы; сборка только `npm run build`.
- Обновлять `SUBSTAGE_CONTEXT.md` при завершении подэтапа.

## Формат ответа о результате

- Что сделано.
- Что проверено и как.
- Что не проверено и почему.
- Следующий безопасный шаг.
