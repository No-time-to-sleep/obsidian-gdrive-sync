# Публикация: community plugins и Google OAuth

Документ фиксирует требования и план выхода в магазин. Часть требований Obsidian нужно перепроверить на актуальной странице документации перед подачей — отмечено в тексте.

## 1. Что требует Obsidian

Из официального репозитория `obsidianmd/obsidian-releases` и документации для разработчиков:

- Публичный GitHub-репозиторий с исходниками плагина.
- `manifest.json` в корне репозитория с полями: `id`, `name`, `version`, `minAppVersion`, `description`, `author`, `authorUrl`, `isDesktopOnly`.
- `versions.json` — совместимость версий плагина с версиями Obsidian.
- GitHub Release с тегом, равным `version` из `manifest.json`, и ассетами `main.js`, `manifest.json`, `styles.css` (если есть).
- `README.md` и лицензия.
- Плагин должен соответствовать developer policies и plugin guidelines (нужно перепроверить актуальную страницу `docs.obsidian.md/Plugins/Releasing/Plugin+guidelines` перед подачей).
- Для мобильной поддержки: `isDesktopOnly: false` и отсутствие Node-специфичных API в runtime-коде.
- Запрещены: телеметрия без явного согласия, обфускация кода, скрытые сетевые вызовы, динамическое исполнение кода (`eval`), доступ к файлам вне vault.
- Сетевые запросы — через `requestUrl`, чтобы работали на mobile.

Заявка подаётся в `obsidianmd/obsidian-releases` (PR), после чего плагин проходит ручное ревью. В списке уже есть плагины с пометкой «not manually reviewed» — им отказывают в публикации до устранения замечаний.

## 2. Имя и id

- Временный id: `gdrive-byo-sync` — проверен на 2026-10-19, коллизий нет.
- Временное имя: `GDrive BYO Sync` — точных коллизий нет.
- Перед подачей:
  - проверить Google brand guidelines: использование «Google Drive»/«GDrive» в названии стороннего приложения может быть ограничено; при необходимости переименовать (например, в нейтральное «Vault Drive Sync»).
  - проверить уникальность финального имени и id по `community-plugins.json`.

## 3. Google OAuth: что важно для магазина

- Scope только `drive.file` (non-sensitive). Верификация Google для публикации **не обязательна**; бренд-верификация — опциональна.
- Плагин не содержит client secret автора: пользователь вставляет свой. Это снимает с автора ответственность за квоты, данные и верификацию, но повышает порог настройки.
- Инструкция по настройке — `GOOGLE_CLOUD_SETUP.md`; она должна быть продублирована в README плагина и, по возможности, в мастере внутри UI.
- Device flow с client type «TVs and Limited Input devices» разрешает `drive.file` (см. `RESEARCH_NOTES.md`).

## 4. Privacy policy и данные

Что должен объяснять плагин пользователю:

- Куда уходят данные: только `accounts.google.com` / `oauth2.googleapis.com` / `www.googleapis.com` (Google), больше никуда.
- Что хранится локально: client secret, refresh token, access token, состояние синхронизации, настройки — в `data.json`.
- Телеметрии нет; аналитика не собирается; содержимое заметок не логируется.
- Пользователь может отозвать доступ и удалить `data.json`.

Рекомендуется добавить `PRIVACY.md` в репозиторий перед публикацией.

## 6. Риски публикации

- **Порог OAuth-настройки.** Многие пользователи не дойдут до конца без видео-гайда; жалобы в отзывах почти неизбежны — их нужно встречать понятным wizard'ом.
- **Ответственность за Google-политики.** Если Google изменит правила device flow, придётся быстро выпускать loopback/relay-вариант.
- **Конкуренция.** В магазине уже десятки Drive-синков; без активного сопровождения плагин потеряется.
- **Поддержка.** BYO-схема означает поток вопросов «почему не работает у меня»; нужны диагностический лог и troubleshooting-раздел.
